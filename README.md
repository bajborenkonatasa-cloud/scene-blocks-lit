# Мои сцены · Scene Blocks Lite 0.1.0

Личное расширение для SillyTavern под последовательность:

**комикс → HTML/CSS артефакт → отдельная иллюстрация.**

Это отдельная реализация идеи G-блока ExtBlocks. Она использует уже настроенный
SillyImages для моделей картинок, стилей и референсов. Для подготовки сцены
выбирается существующий профиль Connection Manager. Новые ключи в этом
расширении вводить не нужно.

## Установка с телефона через GitHub

1. Скачайте `Scene-Blocks-Lite-0.1.0.zip` и распакуйте его в файловом
   менеджере телефона. Откройте полученную папку `scene-blocks-lite`.
2. В браузере войдите в GitHub и откройте https://github.com/new.
3. В **Repository name** напишите `scene-blocks-lite`. Выберите **Public**.
   Оставьте создание README, .gitignore и лицензии выключенным: они уже
   подготовлены в архиве. Нажмите **Create repository**.
4. На странице пустого репозитория нажмите **uploading an existing file**.
   Если репозиторий уже содержит файлы, выберите **Add file → Upload files**.
5. Нажмите **choose your files** и выберите именно эти пять файлов
   **внутри распакованной папки**:

   - `manifest.json`
   - `index.js`
   - `style.css`
   - `README.md`
   - `LICENSE`

6. Дождитесь загрузки и нажмите **Commit changes**. При дополнительном окне
   подтверждения оставьте основную ветку `main` и подтвердите сохранение.
7. На главной странице репозитория файлы `manifest.json`, `index.js`
   и `style.css` должны быть видны сразу, рядом друг с другом.
   Нельзя загружать установочный ZIP вместо этих файлов или помещать их
   внутрь дополнительной папки на GitHub.
8. Скопируйте адрес репозитория вида
   `https://github.com/ВАШ-ЛОГИН/scene-blocks-lite`.
9. В SillyTavern откройте **Расширения → Установить расширение**
   (**Extensions → Install extension**), вставьте этот адрес и установите.
   Обновите страницу Таверны. Откройте появившийся раздел **«Мои сцены»**.

Это публичный репозиторий с кодом. Загружайте только подготовленные файлы:
свои ключи, чаты и экспорты личных настроек в GitHub добавлять не нужно.
GitHub Pages и терминал для этого способа установки не требуются.

В архиве также есть `source-code.zip` — исходный код и тесты для доработок.
Распаковывать и загружать его для обычной установки не требуется.

Официальные инструкции:
[загрузка файлов в GitHub](https://docs.github.com/en/repositories/working-with-files/managing-files-in-a-repository/adding-a-file-to-a-repository),
[установка расширений SillyTavern](https://docs.sillytavern.app/extensions/).

## Установка напрямую в папку SillyTavern

1. Распакуйте папку `scene-blocks-lite` из архива.
2. Поместите **всю папку** в каталог расширений той установки SillyTavern,
   которая обслуживает ваш чат:

   ```text
   SillyTavern/data/<user-handle>/extensions/scene-blocks-lite/
   ```

   Для стандартного пользователя `<user-handle>` обычно равен `default-user`.
   Проверьте папку используемого аккаунта. Итоговый файл должен находиться по
   пути `.../extensions/scene-blocks-lite/manifest.json`, без второй вложенной
   папки `scene-blocks-lite`.

   При установке для всех пользователей можно использовать
   `SillyTavern/public/scripts/extensions/third-party/scene-blocks-lite/`.

3. Обновите страницу SillyTavern. Если расширение не появилось, перезапустите
   сервер SillyTavern и снова обновите страницу.
4. В расширениях откройте **«Мои сцены»**.

Если Таверна находится на хостинге, папку нужно загрузить на сервер через его
файловый менеджер или передать администратору. Копирование на телефон, который
просто открывает этот сайт, не устанавливает расширение на сервер.

Кнопка SillyTavern «Установить расширение» принимает адрес Git-репозитория.
ZIP-файл туда вставлять не нужно. Этот комплект готов к размещению в отдельном
Git-репозитории: его корнем должна быть папка, содержащая `manifest.json`.
Публичный репозиторий в рамках этой сборки не создавался.

## Настройка — один раз

1. Оставьте **SillyImages установленным и настроенным**. Используются его
   действующие параметры генератора и референсы. Проверена структура модулей
   [0xl0cal/sillyimages](https://github.com/0xl0cal/sillyimages), commit
   `752215dc1ff74ba50d23a992bc6d83f31a5eb38e`.
2. В списке **«Промпт из активного набора ExtBlocks»** выберите нужный `comicss`
   и нажмите **«Перенести из ExtBlocks»**. Включённый `comicss` выбирается
   первым по умолчанию. Рядом с одинаковыми именами видны номера и состояния.
   Можно также нажать **«Импорт G-блока»** и выбрать JSON одного блока.
3. Проверьте поле **«Подключение для подготовки сцены»**. Если прежний пресет
   ExtBlocks однозначно связан с профилем, он выберется автоматически.
4. Выключите прежний G-блок `comicss` в ExtBlocks. Остальные нужные вам блоки
   можно оставить. Одновременный запуск двух генераторов одной сцены
   предотвращается проверкой настроек.
5. На копии чата нажмите **«Создать / продолжить»** для последнего ответа.
   После успешной проверки включите **«Автоматически после нового ответа»**.

За один запуск используется один выбранный промпт. Чтобы переключить стиль,
выберите другой G-блок в списке и снова нажмите «Перенести из ExtBlocks».
Если поменяли активный набор в старом расширении, нажмите «Обновить списки».
Исходные варианты в ExtBlocks сохраняются; новый импорт заменяет текущий
промпт только в «Моих сценах». Для всех вариантов действует обязательный
формат: два изображения и HTML/CSS между ними.

Импорт копирует творческий промпт, HTML-шаблон и текстовые элементы контекста
без редактирования их строк. Он переносит число последних сообщений и
доступные параметры API. Пустая ссылка на предыдущий блок игнорируется;
непустые зависимости от других блоков не поддерживаются. После импорта
автогенерация выключена до вашего выбора.

Установочный пример содержит все три обязательные части, запрос 4K, сцены
манхвы, детали и эмоции. Он подходит для неоткровенных сцен. Расширение не
меняет защитные ограничения провайдеров и не реализует обход их отказов.

## Обычное использование

- **«Сцена»** в меню ответа: создать недостающий блок или продолжить его.
- **«Продолжить»**: повторить недостающие картинки. Успешные изображения
  остаются и не генерируются заново.
- **«Повторить комикс» / «Повторить иллюстрацию»**: явно перерисовать только
  выбранную картинку. Это новый запрос к вашему генератору.
- **«Обновить всё»**: заново подготовить HTML и обе картинки. Прежний блок
  сохраняется, пока новый ответ модели не пройдёт проверку структуры.
- **«Стоп»**: остановить очередь или текущую сцену. Готовые части остаются.
- Нажатие на картинку открывает сохранённый файл в полном размере.

Внутри каждой сцены порядок всегда один: первый `img` из ответа модели
становится комиксом, содержимое `<artifact>` — HTML/CSS артефактом, второй
`img` — отдельной иллюстрацией. Вложенную в артефакт вторую картинку расширение
отображает последней. Дополнительные макровставки должны быть нарисованы
внутри комикса; отдельные запросы для них не создаются.

Новый ответ должен содержать ровно два тега
`<img data-iig-instruction='{"prompt":"...", ...}' src="[IMG:GEN]">`
и содержательный HTML/CSS артефакт. При неправильном JSON или неполном ответе
картинки не запускаются: сначала нужно повторить подготовку. При регулярном
обрезании ответа увеличьте лимит токенов в дополнительных настройках.

## Что сделано для устойчивости

- Один запрос к текстовой модели на всю сцену. Комикс и иллюстрация выполняются
  последовательно. Очередь ограничена четырьмя сценами.
- Каждый результат сохраняется в метаданных конкретного сообщения и его
  активного свайпа. Текст ролевого ответа не переписывается.
- Не используется поле `display_text`, которое другие расширения могут
  пересобирать. При загрузке чата интерфейс восстанавливается из метаданных.
- При смене чата, свайпа, редактировании или удалении целевого сообщения
  запоздавшие результаты отбрасываются. Они не записываются в другой ответ.
- Повторные события отображения не запускают ещё одну платную генерацию.
- После ошибки загрузки файла полученные байты временно сохраняются в памяти
  вкладки: повтор загрузки может пройти без новой генерации. После закрытия
  или смены чата эта временная копия не сохраняется.
- При ошибке сохранения чата ссылка остаётся в памяти. Нажмите «Продолжить»
  до перезагрузки страницы. Сервер должен успешно сохранить чат, чтобы
  результат пережил перезагрузку.
- HTML проходит DOMPurify; JavaScript не выполняется. Стили и анимации
  артефакта находятся в Shadow DOM и ограничены его областью. Это также
  означает, что CSS не может менять внешний вид остального чата.
- Вне экрана анимации артефакта можно приостанавливать. Изображения загружаются
  лениво. Постоянного опроса DOM и полного пересчёта чата нет.
- В диагностике нет промптов, текста сообщений, ключей, идентификаторов
  сохранённых ключей, названий профилей или адресов картинок.

Галочка SillyImages «Работа с внешними блоками» для нового формата не требуется:
изображения вызывает и сохраняет очередь «Моих сцен». При этом ссылки могут
дополнительно попадать в альбом SillyImages.

## Совместимость и границы проверки

Проверены контракты API текущих исходников SillyTavern **1.18.0** и указанного
выше SillyImages. Нужен `SillyTavern.getContext().ConnectionManagerRequestService`.
При отсутствии требуемых функций выводится понятная ошибка.

Генератор картинок и его референсы остаются в SillyImages, поэтому изменения
его внутренних модулей в будущих версиях могут потребовать обновления этой
связки. Два изображения 4K и сложная видимая анимация сохраняют свою стоимость
и нагрузку. Эта сборка не ускоряет удалённые серверы генерации.

В расширении нет движка S/A-блоков, произвольного выполнения скриптов,
конструктора зависимостей или редактора API-ключей. Встроенная проверка ищет
дублирующий блок ExtBlocks; она не может определить все возможные конфликты
со сторонними расширениями.

Пройдены 16 тестов очереди и сохранения, а также интеграционная проверка DOM
с имитацией сетевых ответов: разбор HTML, очистка, отображение двух картинок,
повтор после ошибки, сохранение старого результата и выбор нужного промпта
среди одинаковых имён. Настоящие платные запросы к вашим моделям и работа
в вашей установке SillyTavern ещё не проверялись. Браузерная проверка
Chromium в среде сборки не завершилась из-за сбоя запуска браузера;
вид на телефоне нужно проверить после установки.

## Для разработчика

Готовые установочные файлы не требуют npm или сборщика.
DOMPurify берётся из SillyTavern; модули генератора — из установленного
SillyImages. Собственный код написан отдельно, без включения исходников
ExtBlocks или ST-Info-Blocks в архив.

Для разработки распакуйте `source-code.zip`. В нём сохранены модули `src`,
точка входа, тесты и `build.mjs`. Команды `npm install` и `npm run build`
собирают собственные модули в один `index.js` в `dist/scene-blocks-lite`.
Зависимости SillyTavern и SillyImages в этот файл не включаются.

Тесты ядра (Node.js 22+):

```sh
npm test
```

Дополнительная проверка DOM:

```sh
npm install --no-save jsdom dompurify
node tests/dom.mjs
```

Необязательный браузерный тест использует Playwright, DOMPurify и Chromium
из `@sparticuz/chromium`. Можно задать `SCENE_QA_MODULES`, `SCENE_PLAYWRIGHT`
и `SCENE_CHROME` для готового окружения. Тест поднимает временный локальный
сервер и не обращается к платным API.

Основные файлы: `src/core.js` — очередь и сохранение; `src/adapters.js` —
связь с SillyTavern/SillyImages; `src/html.js` — разбор и отображение артефакта;
`src/ui.js` — интерфейс; `src/config.js` — настройки и импорт.

Основа совместимости:
[SillyTavern UI Extensions](https://docs.sillytavern.app/for-contributors/writing-extensions/),
[ExtBlocks](https://gitgud.io/sleepydraqon/ext-blocks-custom),
[SillyImages](https://github.com/0xl0cal/sillyimages).
